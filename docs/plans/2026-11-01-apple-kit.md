# apple-kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `apple-kit` 0.1.0 plugin (Apple Notes CRUD and Apple Health body sync) and wire it into the LifeOS vault and the North Telegram bot.

**Architecture:** The plugin holds two skills and one stdlib-only script, `health_sync.py`, that turns the iPhone Shortcut export into a machine-owned body log. The vault's nutrition scripts read that log, and the 23:20 night job runs the sync. Notes access goes through the `notes` CLI of `macnotesapp`, guarded by approval rules in the skill.

**Tech Stack:** Python 3 stdlib (`unittest`, `json`, `pathlib`), Markdown skills, `macnotesapp` 0.8.3, Claude Code plugin marketplace tooling (`./scripts/cicd.sh`).

**Spec:** `docs/specs/2026-11-01-apple-kit-design.md`

## Global Constraints

- Plugin version `0.1.0` in both `.claude-plugin/marketplace.json` and `apple-kit/.claude-plugin/plugin.json`, with a `CHANGELOG.md` entry `## 0.1.0 — <bump date>`.
- The plugin holds no LifeOS paths. Every vault opinion lives in `.apple-kit.json` at the vault root.
- Bundled files are referenced through `${CLAUDE_PLUGIN_ROOT}`. No `find ~/.claude/plugins`. No reference to another plugin.
- `health_sync.py` uses the Python standard library only.
- The body log is `02Area/Health/Body/body-log.md`, header `| date | time | weight_kg | body_fat_pct | source |`, one row per reading, oldest first, local date and time of the reading.
- Weight rounds to 0.1 kg, body fat to 0.1 %.
- A script never overwrites hand-written content and never changes a body-log cell that has a value.
- Every Notes create, edit, move, or delete needs the user's approval first. Never `--force`. Never `rmdir`.
- The plugin never needs Full Disk Access.
- Vault Python runs with `python3 -B` (no `__pycache__` in the synced vault).
- `CATALOG.md`, `*/README.md`, `site/*` are generated: edit sources, run `./scripts/cicd.sh GEN`.
- Commits happen in `PersonalPlugins` only, after the user approves them. Pushing to `main` (which publishes the public marketplace) needs a separate approval. The LifeOS vault has no version control: back up a vault file before editing it.

## Review Focus

1. The export file is an iCloud placeholder (not downloaded yet): report it as missing with the path, do not crash. Test in Task 1.
2. A weight row in `lb` (the user changes Health units): skip and count it, never store it as kg. Test in Task 1.
3. A reading whose timestamp offset differs from the Mac's time zone: the local date comes from the timestamp's own offset. Test in Task 1.
4. The body log has a hand-added row or a blank line: the sync keeps it unchanged. Test in Task 1.
5. The night job runs while apple-kit is not installed: one warning line, the rest of the job still runs. Test in Task 4.

### Task 1: `health_sync.py` and its tests

**Files:**
- Create: `apple-kit/scripts/health_sync.py`
- Test: `apple-kit/tests/test_health_sync.py`
- Create: `apple-kit/tests/fixtures/export-6.txt` (the 6 observed lines from the spec, verbatim)
- Create: `apple-kit/tests/fixtures/export-15.txt` (the 15-line export with repeated rows: 3 copies, growing, as observed)

**Interfaces:**
- Produces:
  - `Reading = dict` with keys `date: str` (`YYYY-MM-DD`), `time: str` (`HH:MM`), `weight_kg: float | None`, `body_fat_pct: float | None`, `source: str`
  - `parse_export(text: str) -> tuple[dict[tuple[str, str], Reading], int]` — readings keyed by `(date, time)`, plus the skipped-line count
  - `parse_log(text: str) -> tuple[list[str], list[Reading]]` — non-row lines (kept verbatim) and rows
  - `merge(rows: list[Reading], new: dict[tuple[str, str], Reading]) -> tuple[list[Reading], int, int]` — merged rows sorted oldest first, added count, filled count
  - `render_log(rows: list[Reading]) -> str`
  - `stale_line(readings: dict, today: date) -> str | None`
  - `main(argv: list[str] | None = None) -> int` — flags `--config PATH` (required) and `--today YYYY-MM-DD` (tests only)
  - Exit 0 on success and on nothing-new; exit 1 when the export is missing or unreadable, with one line on stdout naming the path.

- [ ] **Step 3: Implement `health_sync.py`** with the interfaces above.
  - Parse with `datetime.fromisoformat`. Keep the timestamp's own offset for date and time (do not convert to the Mac's zone).

  - `stale_line` returns `apple-kit: no new weigh-in for 8 days (last <date>)` only when today minus the newest reading date is exactly 8 days.
  - Print nothing else on success.
